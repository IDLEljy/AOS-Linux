本次完成了 Linux 6.12.114 内核接口调查，为下一次直接编写补丁做准备。

### 已确认的接口

1. **cgroup v2 关联与生命周期**
   - `include/linux/cgroup.h` 提供 `cgroup_get_from_fd()`、`cgroup_put()`、`cgroup_id()`、`cgroup_is_descendant()`。
   - `task_dfl_cgroup()` 可获取任务当前默认层级 cgroup。
   - 保存 cgroup 指针时必须持有引用，并在任务记录销毁时调用 `cgroup_put()`。

2. **路径安全边界**
   - `path_is_under()` 在 `include/linux/fs.h` 声明、`fs/namespace.c` 实现。
   - 该接口同时检查 mount 和 dentry 层级，不能使用字符串前缀判断工作区边界。
   - 新建文件、目录、符号链接、硬链接和 rename 均需要覆盖；创建操作的目标通常由父目录 path 加 pending dentry 表示，不能把 pending dentry 当成已经存在的完整 path。

3. **LSM hooks**
   - `bprm_check_security`：程序执行前检查。
   - `file_open`、`file_permission`、`mmap_file`：打开、读写和映射检查。
   - `path_mkdir`、`path_mknod`、`path_symlink`、`path_link`、`path_rename`、`path_unlink`、`path_rmdir`：路径相关创建/修改检查。
   - `inode_create`、`inode_mkdir`、`inode_symlink`、`inode_link`、`inode_rename` 等 inode hooks 也已核对。

4. **原生 LSM 注册**
   - 使用 `security_add_hooks()` 和 `DEFINE_LSM()`。
   - LSM ID 当前已使用到 `LSM_ID_IPE=113`；新增 AOS ID 需要避免冲突。
   - 需要在 `security/Kconfig`、`security/Makefile` 和 `CONFIG_LSM` 默认列表中接入 AOS。
   - AOS 依赖 `SECURITY`、`SECURITY_PATH`、`CGROUPS` 和 misc device 支持。

5. **控制设备与审计**
   - `struct file_operations` 支持 `unlocked_ioctl` 和 `compat_ioctl`。
   - 可用 miscdevice 注册 `/dev/aosctl`。
   - `audit_log_start()`、`audit_log_format()`、`audit_log_end()` 可用于内核审计；第三方内核事件类型为 `AUDIT_KERNEL_OTHER`。

## 当前设计边界

首版采用小范围、可审查的 MVP：

```text
security/aos/
  Kconfig
  Makefile
  aos_internal.h
  aos_task.c       # Task registry、cgroup 绑定、生命周期
  aos_policy.c     # 工作区/执行文件策略
  aos_lsm.c        # bprm/file/path LSM hooks
  aos_control.c    # /dev/aosctl ioctl
  aos_audit.c      # kernel audit

include/uapi/linux/aos.h
```

建议的安全默认值：

- 未绑定 AOS Task 的进程不改变现有 Linux 行为；
- 受控 Task 默认拒绝工作区外写入和未批准的执行；
- 查询可以读取任务身份和状态，但策略修改只允许受信任管理器；
- `AOS_TASK_FINISH` 后立即撤销任务策略关联；
- ioctl 结构体使用 ABI version、结构体长度和保留字段，所有用户指针必须经过检查；
- 任务对象使用 mutex/引用计数，优先保证生命周期正确性，不使用无锁 MVP；
- cgroup v2 资源限制仍由 `aosd`/systemd 配置，内核 AOS 只记录并关联 cgroup ID。
